# PHP API reference

!!! abstract "What you'll learn"
    - What the generated API reference covers and where to find it.
    - How to build it on your own machine.
    - The docblock conventions that keep it useful.

    **Time:** about 10 minutes · **You'll need:** nothing for reading; PHP 8.2 and Docker (or a phpDocumentor install) for building it locally

## What it is for

The handbook pages explain how the pieces fit together. The API reference answers the narrower question: what exactly does this method take, and what does it return? It is generated by [phpDocumentor](https://www.phpdoc.org/) from the docblocks in the source, so it can never drift from the code. A missing or vague docblock shows up as a missing or vague entry, which is the best reminder to fix it.

## What it covers

The reference is built from `pedalcms.php` and everything under `src/`. That includes the `PedalCMS\Core` classes (`Plugin`, `Program`, `SubpageManager`, `TemplateManager` and the rest) and the template tag functions in `src/template-tags.php` and `src/template-tags-shared.php`. Files named `index.php` are ignored. Templates and admin files are not part of it.

For hooks, use the [Hooks reference](hooks-reference.md) instead. It is generated separately and also covers the hooks fired from templates.

## Where to find it

[Open the PHP API reference](/docs/phpdocs/){ target="_blank" }

The reference lives in the `phpdocs/` folder of the docs repository, next to this user guide, and is published at <https://pedalcms.com/docs/phpdocs/>. It is regenerated for every published Pedal CMS release, so it always matches the released version.

Each Pedal CMS GitHub Release also has a `pedalcms-api-docs-<tag>.zip` attached. It is the reference for that exact version, which helps when you work offline or a site runs an older release. Unzip it and open `index.html`.

!!! note
    The link points to `/docs/phpdocs/`, which is <https://pedalcms.com/docs/phpdocs/> once the docs are published. It does not resolve under `mkdocs serve`, so open `phpdocs/index.html` from the docs repository instead.

## Building it locally

The phpDocumentor configuration and the build script live in the `tools/` folder of the docs repository, and they read a checkout of the plugin. From the root of the docs repository, pass the path to the plugin:

```bash
tools/build-reference.sh ../wp-content/plugins/pedalcms
```

The script needs PHP 8.2. It runs phpDocumentor from a `phpdoc` command if you have one, and otherwise from the `phpdoc/phpdoc:3.10` Docker image. It replaces `phpdocs/`, rebuilds the [Hooks reference](hooks-reference.md) and updates `.reference-tag`. Open `phpdocs/index.html` in a browser when it finishes, then run `git restore phpdocs userguide/docs/developers/hooks-reference.md .reference-tag` to throw the preview away. The committed versions come from the release pull request.

## Docblock conventions

Good entries come from good docblocks. When you add or change a public class, method or function, write one that follows these rules.

- **Summary first.** One sentence that says what it does, written as a statement: "Returns the full URL for a given program action."
- **Add detail after a blank line** only when the behavior is not obvious, such as fallbacks or side effects.
- **`@since`** with the plugin version that introduced it, for example `@since 0.6.4`. If you change behavior later, add a second line such as `@since 0.7.0 Now returns an empty string instead of false.`
- **`@param`** for every parameter, with the type, the name and a sentence: `@param string $action The name of the action.`
- **`@return`** with the type and what it means. Use `@return void` when nothing is returned.
- **Hooks get docblocks too.** Put a docblock directly above every `do_action()` and `apply_filters()` call, with a summary, `@since` and one `@param` per argument, in the order they are passed. The [Hooks reference](hooks-reference.md) reads these.
- **Link related code** with `{@see ClassName::method()}`.

```php
/**
 * Returns the full URL for a given program action.
 *
 * Checks for a local program override before building the URL from the
 * plugin-wide pattern setting.
 *
 * @since 0.1.0
 *
 * @param string $action The name of the action.
 * @param mixed  $program The program ID or WP_Post. Defaults to the current program.
 * @return string The URL of the program action, or an empty string.
 */
```

## Recap

- The API reference covers `pedalcms.php` and `src/`, and is regenerated for every published release.
- It lives in `phpdocs/` in the docs repository and is published at <https://pedalcms.com/docs/phpdocs/>; to preview changes before a release, build it with `tools/build-reference.sh` in the docs repository.
- Summaries, `@since`, `@param` and `@return` make the reference and the hooks reference useful.
